# i18n Standard (Frontend)

Robo MultiPost uses a frontend-first i18n model:

- Default locale: `pt-BR`
- Secondary locale: `en`
- Locale state: persisted in `src/stores/app-store.ts`
- Translator hook: `useI18n()` from `src/lib/i18n/use-i18n.ts`
- Dictionaries:
  - `src/lib/i18n/messages/pt-BR.ts`
  - `src/lib/i18n/messages/en.ts`

## Mandatory Rules

1. Never ship new frontend UI with hardcoded user-facing strings.
2. Wrap all visible text with `t("...")`:
   - headings, labels, helper text, placeholders
   - empty states, dialogs, button labels
   - aria labels and tooltip text
3. Toasts and error messages must be localized:
   - use `t(...)` directly for known messages
   - use `translateErrorMessage(error, t, "Fallback key")` for unknown/runtime errors
4. Add every new PT-BR key to `src/lib/i18n/messages/pt-BR.ts`.
5. Keep EN as fallback (via key text or explicit `en.ts` mapping when required).
6. For date/time strings, use helpers in `src/lib/i18n/date.ts`.

## Implementation Pattern

```tsx
"use client";

import { useI18n } from "@/lib/i18n/use-i18n";
import { translateErrorMessage } from "@/lib/i18n";
import { toast } from "sonner";

export function Example() {
  const { t } = useI18n();

  async function handleAction() {
    try {
      // action
      toast.success(t("Saved successfully"));
    } catch (error) {
      toast.error(translateErrorMessage(error, t, "Failed to save"));
    }
  }

  return <button>{t("Save")}</button>;
}
```

## PR Checklist (Frontend Changes)

- [ ] All new user-facing strings use `t("...")`
- [ ] Toast messages are localized
- [ ] Added/updated keys in `pt-BR.ts`
- [ ] EN fallback behavior preserved
- [ ] Date/time output is locale-aware where applicable
