# X (Twitter) — Configuração Passo a Passo

Este guia explica como conectar sua conta do X (antigo Twitter) ao Robô MultiPost usando o modo **BYO (Bring Your Own OAuth)**.

---

## Pré-requisitos

- Uma **conta no X** ([x.com](https://x.com))
- Uma **conta de Desenvolvedor no X** — [developer.x.com](https://developer.x.com/)
- **Plano Free ou superior** da API do X

> **Sobre os planos:** O plano Free permite até 1.500 tweets por mês. Para maior volume, considere os planos Basic ou Pro.

---

## 1. Crie um Projeto e App no Portal de Desenvolvedores

1. Acesse [developer.x.com](https://developer.x.com/) e faça login
2. No Dashboard, clique em **"Create Project"**

![Portal do Twitter Developer](/docs/twitter-developer-portal.png)

3. Preencha:
   - **Project Name** — ex: "Meu Robô de Posts"
   - **Use Case** — selecione "Making a bot" ou "Managing Tweets"
4. Crie um **App** dentro do projeto:
   - **App Name** — ex: "robo-multipost"

---

## 2. Configure a Autenticação OAuth 2.0

1. No app criado, vá em **Settings > User authentication settings**
2. Clique em **"Set up"**

![Configurações do App Twitter](/docs/twitter-app-settings.png)

3. Configure:
   - **App permissions:** Read and Write
   - **Type of App:** Web App, Automated App or Bot
   - **Callback URI / Redirect URL:**

**Produção:**
```
https://seu-dominio.com/callback
```

**Desenvolvimento local:**
```
http://localhost:3000/callback
```

4. **Website URL:** Coloque a URL do seu domínio (obrigatório)
5. Clique em **"Save"**

> **Importante:** O X usa OAuth 2.0 com PKCE (Proof Key for Code Exchange). O Robô MultiPost gerencia isso automaticamente durante o fluxo de conexão.

---

## 3. Obtenha o Client ID e Client Secret

Após configurar o OAuth 2.0:

1. Vá em **Keys and Tokens**
2. Na seção **OAuth 2.0 Client ID and Client Secret**:
   - Copie o **Client ID**
   - Copie o **Client Secret**

> **Atenção:** O Client Secret só é exibido uma vez. Se perder, será necessário regenerar.

---

## 4. Cadastre as Credenciais no Dashboard

1. No Robô MultiPost, vá em **Contas** > **"Conectar Conta"**
2. Selecione **X (Twitter)** como plataforma
3. Selecione o método **BYO OAuth**
4. Preencha:
   - **APP ID** — cole o Client ID
   - **APP SECRET** — cole o Client Secret
5. Clique em **Salvar**

---

## 5. Conecte sua Conta

1. Clique em **"Conectar"** na conta cadastrada
2. Você será redirecionado para o X para autorizar o acesso
3. Clique em **"Authorize app"**
4. Após autorizar, você será redirecionado de volta ao sistema
5. A conta aparecerá conectada na lista

---

## Permissões Necessárias

O app solicita os seguintes scopes durante a autorização:

| Scope | Descrição |
|-------|-----------|
| `tweet.write` | Permite criar e publicar tweets |
| `users.read` | Lê informações do perfil do usuário |
| `offline.access` | Permite refresh do token (acesso contínuo) |

---

## Tipos de Publicação Suportados

| Tipo | Descrição | Requisitos |
|------|-----------|------------|
| **Texto** | Tweet com texto | Até 280 caracteres (Free) ou 25.000 (Premium) |
| **Imagem** | Tweet com imagens | Até 4 imagens (JPEG, PNG, GIF) |

---

## Limites da API

| Plano | Tweets/mês | Leitura |
|-------|-----------|---------|
| **Free** | 1.500 | 1.500 tweets |
| **Basic** | 3.000 | 10.000 tweets |
| **Pro** | 300.000 | 1.000.000 tweets |

> **Dica:** Para a maioria dos usuários, o plano Free é suficiente para agendamento básico.

---

## Solução de Problemas

### Erro "Invalid redirect_uri"
- Verifique se o Callback URI está configurado em **User authentication settings**
- A URL deve corresponder exatamente à exibida no dashboard
- O X não aceita URLs com porta diferente da configurada

### Erro "Unauthorized" ao publicar
- Verifique se o app tem permissão **Read and Write** (não apenas Read)
- Confirme que o token não expirou — o sistema deve renovar automaticamente via `offline.access`

### Erro "Rate limit exceeded"
- Você atingiu o limite de publicações do seu plano
- Aguarde o reset do período (mensal)
- Considere fazer upgrade para um plano com maior limite

### Token expira frequentemente
- Certifique-se de que o scope `offline.access` foi concedido
- O sistema renova tokens automaticamente, mas se falhar, desconecte e reconecte a conta

### Erro "PKCE verification failed"
- Isso pode ocorrer se o fluxo de autorização for interrompido
- Tente desconectar e reconectar a conta
- Limpe os cookies do navegador para o domínio do X
